What if one computer
could become many?

Virtualization is software that divides one physical machine into several independent computers. Each one has its own operating system, files and applications, and each behaves as if it were running on dedicated hardware.

Meet your
virtual computer.

A virtual machine (VM) is a software-defined computer. Everything it uses is virtual hardware, but the guest OS sees a complete machine.

Virtual CPU

Threads that the hypervisor schedules onto real cores in short time slices.

Memory

A reserved range of host RAM. The guest believes it is physical memory.

Storage

A virtual disk, usually a file or volume on real drives or a SAN.

Virtual network

A software adapter linked to a virtual switch, then to the real network.

Guest OS

Boots from the virtual disk exactly as it would on real hardware.

Applications

Run inside the guest and cannot tell the machine is virtual.

The intelligence
behind it all.

Meet the hypervisor. Select a layer to learn what it does.

Virtual machines

Complete guest computers with their own OS. Each sees only the virtual hardware it was given and cannot see its neighbours.

The hypervisor

Creates VMs, schedules CPU time, maps guest memory to physical memory and mediates every device access. It enforces the boundaries between VMs.

Physical hardware

Real CPU cores, RAM, disks and network cards. They are the only real resources and are shared among all VMs.

Six steps from bare machine to running workloads.

Hardware
Hypervisor
CPURAMDisk
  1. 01

    Hardware provides resources

    CPU cores, RAM, storage and network adapters form a pool of real capacity.

  2. 02

    Hypervisor manages hardware

    It starts first (or as a host component) and takes control of the pool using CPU virtualization extensions.

  3. 03

    Virtual machines are created

    Each VM is a definition: how many vCPUs, how much memory, which disk files, which virtual network.

  4. 04

    CPU and memory are allocated

    vCPUs are scheduled onto cores in turn. Guest memory pages are mapped to host pages and tracked.

  5. 05

    Operating systems boot

    Virtual firmware loads each guest OS from its virtual disk. The guest sets up drivers for virtual devices.

  6. 06

    Applications run independently

    Workloads run side by side. The hypervisor keeps their memory and devices separate.

A vCPU is not a dedicated core. Virtual allocation is a scheduling promise; the hypervisor decides which real core runs each vCPU at each moment. Memory is usually overcommitted carefully and backed by host RAM.

Virtualization
is everywhere.

Cloud computing

Every cloud instance you rent is a VM sharing a physical host.

Enterprise data centers

Live migration moves running VMs between hosts with little or no downtime.

Software development

Reproducible test environments for every OS and configuration.

Cybersecurity testing

Malware analysis and attack practice in disposable, snapshot-able labs.

Disaster recovery

VM images replicate to another site and restart on different hardware.

Server consolidation

Dozens of lightly used servers become VMs on a few busy hosts.

Benefits.
Trade-offs.

Why it matters

  • Higher hardware utilization and lower cost
  • Fast provisioning and cloning from templates
  • Snapshots and easy rollback of broken changes
  • Strong isolation for multi-tenant workloads

What to watch

  • Hypervisor adds some overhead
  • Overcommitted hosts can slow every VM
  • The host is a shared point of failure
  • VM sprawl needs governance and monitoring

Glossary

Hypervisor

Software that creates, runs and isolates virtual machines.

Host and guest

The host is the physical machine (and its hypervisor). A guest is a VM running on it.

vCPU

A virtual processor presented to a guest. It runs on whichever physical core the hypervisor picks.

Snapshot

A saved state of a VM's disk and memory that can be restored later.

Container vs VM

Containers share the host kernel and are lighter. VMs include their own kernel and are more strongly isolated.
